# Regras obrigatórias

1. **Nunca** colocar lógica de negócio no Controller — Controllers reais (`TaskController`) só chamam `userObject()`, delegam ao Service injetado no método, e embrulham o retorno em `self::successResponse()`/`self::returnError()`.
2. **Nunca** colocar queries (`Model::where`, `DB::table`, `DB::select`, `->get()`, `->first()`) no Controller. No Service, é aceitável chamar o Model do Eloquent diretamente para operações simples (`Task::create(...)` em `CreateTaskService`) — só use Repository quando a query for complexa/reaproveitada (ver `architecture.md`).
3. **Nunca** retornar `response()->json()` diretamente no Controller — usar `self::successResponse()`. Para erros, usar **`self::returnError($exception)`** (não `errorResponse()` — esse nome não existe na trait `Response` real deste projeto, ver `utilities.md`).
4. **Sempre** usar `DB::transaction()` em qualquer Service que faça alteração no banco (confirmado em `CreateTaskService::execute()`).
5. **Nunca** usar valores literais para representar conceitos de domínio fechados — usar Enum. Único Enum confirmado no código real hoje é `App\Packages\Auth\Auth\Enum\SettingsEnum`; `TaskStatus`/`TaskPriority` são tabelas de banco com coluna `slug` (`status.slug`, `priority.slug`, visto em `TaskRepository::listWithFilters()`), consultadas por `slug`, não por Enum PHP. Se for necessário comparar status/prioridade em lógica de negócio nova, prefira comparar pelo `slug` da tabela (estável) — não pelo `id` (UUID gerado, mas ainda assim não é um "código de domínio" memorizável) nem por Enum inexistente; se o time decidir criar um Enum de slugs conhecidos (`TaskStatusSlugEnum`), é uma decisão a alinhar antes, não a fazer de passagem.
6. **Nunca** usar status HTTP como número literal em regra de negócio nova — mas note que o próprio `App\Base\Traits\Response` real usa números literais internamente (`return response()->json($response, 404);`, `500`, `400`) em vez de `Symfony\Component\HttpFoundation\Response::HTTP_*` — é um padrão já presente na trait-base, não corrija a trait sem pedido; em código de domínio novo (Controllers/Services), prefira as constantes do Symfony quando praticável.
7. **Nunca** ter mais de um nível de indentação por método — extrair para método privado quando precisar de outro bloco de controle.
8. **Evitar `else`** — preferir retorno antecipado ou extração de método (visto em `AuthenticateMiddleware::checkIfTokenIsValid()`, que usa apenas `if` + `return` em sequência).
9. **Sempre** declarar `$table` com schema qualificado quando o schema não é `public` (`admin.users`, `admin.roles` — ver `Model::class` referenciado em `config/auth.php`: `App\Packages\Admin\Users\Models\User`). Tabelas do domínio `Task` usam `public.tasks`, `public.task_statuses`, `public.task_priorities` — qualificação explícita mesmo em `public` (padrão real observado em `Task.php`: `protected $table = 'public.tasks';`).
10. **Sempre** declarar `$fillable` no Model.
11. **UUID como chave primária em Models de domínio**: `use HasUuids;` + `public $incrementing = false;` + `protected $keyType = 'string';` — confirmado em `Task`. Ao criar Model novo, siga esse padrão a menos que a tabela já exista com `bigIncrements` (não force a migração de PK em tabela existente).
12. **Sempre** criar um Service por ação (não um Service por entidade com múltiplos métodos) — padrão real confirmado em `Task/Tasks/Services/` (6 Services para 6 ações).
13. **Injeção de Dependência**: nova dependência entra pelo construtor. `app(AlgumService::class)` aparece dentro de `AuthenticateMiddleware` (`app(TokenInCacheService::class)->execute($token)`) — padrão já presente no middleware real, não é uma violação a corrigir em massa, mas não reproduza em Controllers/Services novos.
14. **Nunca** acessar `->first()->propriedade`/`->find()->propriedade` sem checar `null` antes.
15. **Nunca** posicionar `throw`/validação que lança exceção após uma operação de escrita fora de `DB::transaction()`.
16. **Nunca** interpolar valores em SQL cru. `TaskRepository::listWithFilters()` já demonstra o padrão correto: os fragmentos de `WHERE` condicionais são montados por concatenação de **texto fixo de coluna**, mas os **valores** entram só por bind nomeado (`:user_id`, `:search`, `:status_id`, `:priority_id`, `:due_date`) via array `$params` passado a `DB::select($query, $params)` — nunca o valor do usuário é interpolado na string SQL. Siga exatamente esse padrão em queries novas com filtro dinâmico: o texto condicional (`"AND T.status_id = :status_id"`) pode ser montado dinamicamente, o valor nunca.
17. **Nunca** declarar tipo de retorno `mixed` quando o tipo é conhecido — `App\Base\Repository\BaseRepository` já usa `mixed` extensivamente na base (não corrigir a base sem pedido), mas Services/Repositories de domínio novos devem tipar concretamente (ver `CreateTaskService::execute(): TaskResource`, `TaskRepository::listWithFilters(): LengthAwarePaginator`).
18. **Nunca** usar `LIMIT`/`->first()` sem `ORDER BY` quando a query pode retornar mais de uma linha.
19. **Sempre** modelar controle de acesso como allow-list — `AuthenticateMiddleware` já segue esse padrão (`array_intersect($abilities, $permissions)` com `count` igual, exigindo todas as abilities pedidas).
20. **Sempre** importar classes com `use` no topo em código PHP novo — nunca FQCN inline (⚠️ `routes/api.php` já viola isso hoje, ver `naming.md`/`architecture.md` — não é padrão a seguir).
21. **Sempre** representar ausência de dado como `null`, nunca objeto/array vazio com campos nulos.
22. **Sempre** rodar o Pint no(s) arquivo(s) alterado(s) antes de considerar a tarefa concluída (ver `formatting.md`).
23. **Nunca** adicionar comentário que só descreve o que o código já diz — só para decisão não-óbvia, achado real ou workaround. `CreateTaskService::execute()` já tem um comentário nesse limite (explica por que o cache é limpo por prefixo em vez de chave exata) — siga esse padrão de "porquê", não "o quê".
24. **Não introduza DTO numa Service nova sem pedido explícito** — nenhuma Service do domínio usa DTO hoje; todas recebem `array` (`$request->validated()`) direto. `spatie/laravel-data` estava instalado sem uso real e foi removido do `composer.json` em 2026-07-27; se um DTO for necessário no futuro, alinhe com o time antes de reinstalar um pacote.
